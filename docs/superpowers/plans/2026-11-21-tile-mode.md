# Tile Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a second fitting mode to Notan that fits straight-edged tiles which share edges and never overlap, built as a tree of ever smaller tiles, with two cut orders (strict tree, worst first).

**Architecture:** A `TileMesh` holds a tree of tiles over shared corners. Each stage, a CPU search picks a straight cut for the leaves with the most to gain; the existing Metal rasteriser, fed polygon edges directly, then moves corners and colours by gradient descent. Prefix moves only the new cut ends along frozen edges; Re-fit moves every corner and guards the tiling's validity. Results reach the app as `Picture.tiles`, so levels, display, export and the window reuse what exists.

**Tech Stack:** Swift, MLX Swift 0.33.0 (existing Metal kernels in `RasterKernels`), Core Graphics, SwiftUI, XCTest.

**Spec:** `docs/superpowers/specs/2026-11-21-tile-mode-design.md`

## Global Constraints

- MLX Swift stays pinned at exactly 0.33.0. Builds and tests go through `xcodebuild`, never plain `swift build`.
- `NotanCore` imports no SwiftUI or AppKit.
- Curve mode is unchanged: every existing test stays green without edits, except `FitModelTests` lines that index `results` (Task 8).
- A tiling is always valid: every leaf tile is a simple polygon with positive area, and the leaves' areas add up to the picture's.
- Fits are reproducible: the same photo and settings give identical levels.
- `RasterKernels` is not edited. Tiles reach it through `Rasterizer`.
- Test command, whole suite: `xcodebuild test -scheme Notan-Package -destination 'platform=macOS,arch=arm64' -derivedDataPath .build/dd`. One class: add `-only-testing:NotanCoreTests/<Class>` (or `NotanAppTests/<Class>`). "Run" below means this command; pass means `** TEST SUCCEEDED **`.

## Review Focus

1. **A photo, or a tile, that is one flat colour.** Every cut has zero gain. Expect: fitting still finishes, the order of cuts is the same on every run, no NaN colours. Test in Task 5.
2. **More tiles asked for than fit** (tiny working size, or Min width large). Expect: fitting stops early with fewer levels and tiles, no crash, no tile below the limits. Test in Task 5.
3. **Seams at a display scale that is not a whole number.** Expect: no pixel of the background colour between tiles. Test in Task 2.
4. **Re-fit with a corner pushed across a neighbouring tile in one step.** Expect: the corner goes back, the tiling stays valid, other corners keep their move. Test in Task 6.
5. **Changing kind or pressing Restart while a tile fit runs.** Expect: the old fit's results are not filed under the new variant. Test in Task 8.

```swift
// Model.swift
public struct Tile: Equatable, Sendable {
    public var corners: [SIMD2<Float>]   // in order round the tile
    public var color: RGB
    public var path: [Int]               // 0 or 1 at each cut from the root; [] is the whole picture
    public init(corners: [SIMD2<Float>], color: RGB, path: [Int])
}

// TileMesh.swift
public func polygonArea(_ polygon: [SIMD2<Float>]) -> Float      // sum of (x_i*y_j - x_j*y_i)/2, j = i+1; positive for a valid tile
public func isSimplePolygon(_ polygon: [SIMD2<Float>]) -> Bool   // no two non-adjacent edges cross or touch

public struct CutEnd: Equatable, Sendable {
    public var edge: Int     // the tile's edge from corner `edge` to corner `edge + 1`
    public var t: Float      // how far along it, strictly between 0 and 1
    public init(edge: Int, t: Float)
}
public enum Freedom: Equatable, Sendable {
    case fixed, alongX, alongY, free
    case slide(from: Int, to: Int)       // on the frozen segment between two points
}
public struct TileNode: Equatable, Sendable {
    public var corners: [Int]            // point indices; empty once the tile is cut
    public var color: RGB
    public var path: [Int]
    public var children: [Int]           // empty, or two node indices
    public var stage: Int                // the stage that made it; 0 for the root
}
public struct TileMesh: Equatable, Sendable {
    public let width: Int
    public let height: Int
    public private(set) var points: [SIMD2<Float>]
    public private(set) var freedom: [Freedom]
    public private(set) var nodes: [TileNode]            // nodes[0] is the root
    public init(width: Int, height: Int, color: RGB)     // corners (0,0) (w,0) (w,h) (0,h), all .fixed
    public var leaves: [Int]                             // node indices, ascending
    public func polygon(_ node: Int) -> [SIMD2<Float>]
    @discardableResult
    public mutating func cut(_ leaf: Int, from: CutEnd, to: CutEnd, stage: Int, shareCorners: Bool)
        -> (first: Int, second: Int)
    public mutating func setPoint(_ index: Int, _ point: SIMD2<Float>)
    public mutating func setColor(_ node: Int, _ color: RGB)
    public func invalidLeaves(minArea: Float) -> [Int]   // leaves that are not simple or have area < minArea
    public func tiles() -> [Tile]                        // the leaves, in `leaves` order
}
```

`cut` rules, which the tests pin: with `from.edge = i`, `to.edge = j`, `i != j`, new points A (on edge i) and B (on edge j) are appended to `points` in that order. The first child has corners A, corner i+1 … corner j, B and path `parent + [0]`; the second has B, corner j+1 … corner i, A and path `parent + [1]`. Both start in the parent's colour. With `shareCorners == false` each new point's freedom is `.slide(from:to:)` between the two ends of its edge and no other tile changes. With `shareCorners == true` each new point is also inserted into the one other leaf that has the same edge reversed, if there is one; its freedom is `.alongX` if both edge ends have y == 0 or both y == height, `.alongY` likewise for x, else `.free`.

### Task 3: Finding the best cut (`CutSearch`)

**Files:**
- Create: `Sources/NotanCore/CutSearch.swift`, `Tests/NotanCoreTests/CutSearchTests.swift`

**Interfaces:**
- Consumes: `CutEnd`, `polygonArea`, `isSimplePolygon` (Task 1); `TargetImage`.
- Produces:

```swift
public struct CutChoice: Equatable, Sendable {
    public var from: CutEnd
    public var to: CutEnd
    public var gain: Float          // how much the summed squared error falls, >= 0
    public var firstColor: RGB      // mean colour of the side that becomes TileMesh.cut's first child
    public var secondColor: RGB
}
public func thickness(of polygon: [SIMD2<Float>]) -> Float   // 2 * area / perimeter
public let minTileArea: Float = 4
public func bestCut(
    of polygon: [SIMD2<Float>], in target: TargetImage, minThickness: Float, candidates: Int = 32
) -> CutChoice?
```

Algorithm (not determined by the signature): spread `candidates` points round the outline in proportion to edge length, at least one per edge, at fractions `(k + 0.5) / n` of their edge. Try every pair on different edges, lower edge index as `from`. Reject a pair if the segment leaves the polygon (its midpoint is outside, or it crosses an edge), or if either piece has area below `minTileArea` or thickness below `minThickness`. The tile's pixels are those whose centres lie inside it; a pixel's side is the sign of the cross product with the cut. With per-side sums S and counts n, gain = |S1|²/n1 + |S2|²/n2 − |S1+S2|²/(n1+n2), summed over channels; a pair with an empty side is rejected. Keep the largest gain; on a tie keep the first found. Nil when no pair survives.

public struct TileEdgeLayout {

    public let edgeCount: Int              // most corners of any tile, rounded up to a multiple of 4, at least 8
    public init(tiles: [[Int]])            // each tile's corner indices

How `edges` pads (the kernels need one edge count for all tiles, and are compiled once per count, hence the rounding): a tile with n corners gets its first edge divided into `E − n + 1` equal parts, so no edge has zero length. Each outline point is `(1 − w) * points[a] + w * points[b]` from stored index arrays `a`, `b` and weights `w` ([T, E]), built with `take`, so MLX differentiates it.

```swift
// Model.swift
public enum ShapeKind: String, Sendable, CaseIterable { case curves, tiles }
public enum TileOrder: String, Sendable, CaseIterable { case tree, worst }
extension FitSettings {                    // stored properties
    public var kind: ShapeKind             // default .curves
    public var tileOrder: TileOrder        // default .worst
}
/// Cuts per stage; they add up to totalTiles - 1.
public func tileSchedule(totalTiles: Int, order: TileOrder) -> [Int]
    // .tree: 1, 2, 4, 8, … with the last entry cut short; .worst: stageSchedule(totalShapes: totalTiles - 1)

// TileFitter.swift
public struct TileFitter {
    public let target: TargetImage
    public let settings: FitSettings
    public let loss: LossConfig
    public static let baseRefreshInterval = 10
    public init(target: TargetImage, settings: FitSettings, loss: LossConfig = .init())
    /// Blocking. Returns the levels finished so far, level 0 first, when done or cancelled.
    public func run(progress: (FitProgress) -> Void, isCancelled: () -> Bool) -> [Level]
}
```

The stage loop (this task implements `settings.mode == .prefix`; `.refit` may take the same path for now):

1. `mesh = TileMesh(width, height, color: target.meanColor)`. Level 0 is that one tile. Every level is `Level(picture: Picture(width:height:background: target.meanColor, shapes: []) with tiles = mesh.tiles(), mse: measuredMSE(…))`, reported through `progress` with `finishedLevel` set, as `Fitter` does.
2. For each entry `n` of `tileSchedule(totalTiles: settings.totalShapes, order: settings.tileOrder)`: call `bestCut` for every leaf with `minThickness: max(1, settings.minWidth)`; take the `n` with the largest gain, ties to the lower node index. If there are none, stop: no further levels. Apply them with `mesh.cut(…, shareCorners: settings.mode == .refit)` and give the children the choice's colours.
3. Optimise for `settings.stepsPerStage` steps. Movable tiles are this stage's children. Parameters: for each new cut end its distance in pixels along its edge (start: the choice's `t` times the edge length), and the children's colours. Learning rates 1.0 × (long side / 256) and 0.01, as `Fitter`. Points are the frozen points with the new ones computed as `from + distance * unit direction`.
4. Each step: `image, boundary = rasterizer.render(edges: layout.edges(points:), colors:, background:, crops:, over: base)`, loss `tileLoss`, gradient inside `onOneStream`, Adam step, clamp colours to 0…1 and each distance to 5%…95% of its edge. `base` is the soft render of the whole current tiling over the mean colour, with its boundary distance, wrapped in `stopGradient`, recomputed at step 0 and every `baseRefreshInterval` steps. Crops are each movable tile's `cropRect` with `Fitter`'s margin, recomputed at the same times. Report progress every `Fitter.progressInterval` steps and check `isCancelled` every step.
5. Write points and colours back to the mesh and finish the level.

### Task 6: Fitting tiles, Re-fit

**Files:**
- Modify: `Sources/NotanCore/TileFitter.swift`, `Tests/NotanCoreTests/TileFitterTests.swift`

**Interfaces:**
- Consumes: Task 5; `TileMesh.freedom`, `TileMesh.invalidLeaves`, `TileEdgeLayout.areas`, `LossConfig.tileAreaWeight`.
- Produces:

```swift
/// Puts back the corners of tiles that are no longer valid. `previous` holds every point's
/// position before the step. Corners of the invalid leaves return to it; if the tiling is
/// still invalid, every point does.
func revertInvalid(_ mesh: inout TileMesh, previous: [SIMD2<Float>], minArea: Float)
```

When `settings.mode == .refit`, step 3 of Task 5 changes: movable tiles are all leaves; parameters are all points and all leaf colours. Before the Adam step the points' gradient is multiplied by a mask from `freedom` (`.fixed` 0,0; `.alongX` 1,0; `.alongY` 0,1; `.free` 1,1). The loss adds `config.tileAreaWeight * sum(max(minTileArea − areas, 0)) / minTileArea`. After every step the points are read back, written to a copy of the mesh, and `revertInvalid(…, minArea: 1)` is applied; if it changed anything the parameter array is rebuilt from the mesh.
